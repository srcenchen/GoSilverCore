# 项目审计与修复记录

日期：2026-10-22。覆盖启动入口、界面、发现、GSP 编解码、客户端、服务器、调度、分块、连接池、内存池、SDK 和测试。保留工作区已有修改，在其基础上改动；旧 TUI 及其依赖已移除。

## 已修复

| 问题 | 影响 | 修复 |
|---|---|---|
| TUI 事件中同步发现、连接、分块和广播 | 点击后界面无法响应 | 默认嵌入 WebUI；任务异步执行，按钮忙碌状态、错误提示和 SSE 推送 |
| 未就绪状态直接读取空文件元数据 | 连接失败 / EOF / 崩溃 | 节点就绪与文件就绪分离，命令服务可独立启动；无文件与源文件变化返回可读错误 |
| 注册和 Watch 使用两个连接，注册无确认 | 推送无法送达、断线检测错误 | 独立注册连接，确认后在同一连接监听，SDK 统一关闭 |
| 无限制拨号、坏连接回池、截止时间遗留 | 后续请求长时间等待、EOF | 每地址有界借用、4 秒拨号超时、失败丢弃；归还清除客户端截止时间，每次服务端响应刷新写截止时间；空闲一分钟的连接主动淘汰 |
| 失败分块无限重试，取消不打断网络；部分路径未等待子协程 | 卡住、资源泄漏、文件已关闭仍写入 | 5 个工作协程、最多 3 次尝试、上下文中断、汇合后清理 |
| 每个节点启动时预分配 50 × 4 MiB 缓冲区 | 每节点立即占用约 200 MiB | 延迟分配、非阻塞借用、最多缓存 16 块；控制请求使用小缓冲区 |
| 下载块多余复制，读写通过单通道串行化；发送端首次重复读块算 CRC | 多次内存复制、I/O 并发被抵消 | 直接校验写入、使用 ReadAt / WriteAt、读块一次后计算 CRC |
| 同一块被多台机器请求时共享租约 | 并发计数错误、调度不准确 | 按接收机器 ID + 分块索引跟踪租约，失败节点移除对应拥有记录 |
| 按 IP 推断请求者 | 同机多实例或共享地址的机器身份不明确 | 下载请求显式携带接收端 UUID |
| 接收完成即关闭文件和服务 | 已完成机器无法继续做种 | 完成文件由 Session 保留至停止；下次任务替换时关闭旧描述符 |
| Stop 仅关闭监听、不关闭已建立连接 | 退出慢、Watch 和请求泄漏 | 跟踪连接、全部关闭、等待处理协程，释放文件与池 |
| mDNS 依赖访问外网路由；完成事件与最后记录竞态；缓存过期记录 | 无外网时发现失败、误报未发现或多个发送端 | 枚举私有 IPv4 网卡；查询结束后才读取第三方库发布的可变记录指针并排空通道；验证发送端在线及就绪，同实例地址合并 |
| 接收端重复连接复用旧地址、地址被禁用 | 无法改地址或恢复发现 | 地址始终可编辑，接收模式默认持续轮询发现、上线自动连接、断线自动重连，保留手动直连入口 |
| 同一实例可以同时启动两种角色 | 角色混乱、生命周期交叉 | 后端互斥；默认选择一种角色，`-mode` 直接进入，停止后切换 |
| 写入目标没有完整预检查 | 权限、文件冲突等问题到正式启动才暴露 | 按机器检查目标目录和每个文件、实际写权限、覆盖规则、磁盘空间；启动再检查，失败机器排除 |
| 文件路径与块长度未充分校验 | 越界写入、目录穿越、畸形帧崩溃 | 块索引 / 长度 / 元信息 / 帧大小 / 文件清单校验，归档条目约束 |
| 远端已启动任务但确认丢失时取消 | 远程任务继续执行 | 任务 ID 贯穿启动、轮询、取消；取消按 ID 匹配，命令终止进程组 |
| 状态快照返回可变操作指针 | HTTP / SSE 序列化时可能发生数据竞争 | 在锁内复制快照；多机更新使用独立映射 |
| 无条件分发只覆盖当前列表 | 后续上线设备无法加入同一任务 | 持续发现已连接节点，使用同一任务 ID 逐机预探测并加入；停止接纳不打断已有接收与做种 |
| 文件与命令共用任务状态及取消入口 | 单独命令依赖文件，状态互相覆盖 | 独立服务、操作与任务通道；命令和文件可并行，分别取消 |
| 页面旧令牌被拒绝后需要刷新 | 操作中断，表单丢失 | 保留同源校验，自动刷新会话令牌；明确拒绝才重试一次，SSE 退避重连 |
| 默认固定 WebUI / 发送端端口 | 多实例或遗留进程造成启动失败 | 默认全部使用端口 0，显示并通过 mDNS 发布实际端口 |
| 远程调度改进与本次下载重构重叠 | 合并可能恢复旧 TUI、无限重试或错误租约计数 | 保留 WebUI、有界重试和按接收机器归还租约；整合机房局部性、多候选故障转移、库快照与文件名清洗；补种指令复用有界下载协程 |
| 测试 API 过期、依赖本地 APK、固定端口并无限等待 | 无法编译，无法自动回归 | 临时目录和端口，限定测试时间，增加协议和多节点集成测试 |

## 新增流程

文件或文件夹选择 / 流式上传 → 单实例分发模式 → 接收端发现或直连 → 发送端指定目标路径 → 分机预探测 → 仅启动通过的机器 → 进度 / 校验 / 展开 → 接收完成、继续做种 → 主动下线后任务结束。

“无条件分发”持续接纳当前及后续设备，同一次任务使用同一 ID；不可用设备仍排除。命令可在无文件的发送服务上独立执行，与文件任务分别管理状态、输出及取消。

接收端不配置保存根目录，默认允许命令执行，控制密钥可选。具体行为按本次需求实现；绝对路径和命令由接收机器的操作系统执行，受程序运行账户的实际权限约束。

## 性能验证

原实现每个 MemPool 在构造时预分配约 200 MiB。修改后构造不分配任何文件块；在本机 darwin/arm64 的 Go 基准中：

| 基准 | 时间 | 内存 | 分配 |
|---|---:|---:|---:|
| PoolStartup | 约 58 ns/op | 240 B/op | 2 allocs/op |
| CachedBuffer | 约 14 ns/op | 0 B/op | 0 allocs/op |

这些是内存池微基准，不代表实际局域网吞吐量。下载顺序使用常量内存的分块排列，不随分块数量创建索引数组或协程。

## 验证与边界

- `go test -race ./...`：多机文件及文件夹分发、无效机器排除、后续设备自动加入同一任务、暂停接纳后继续接收、绝对目标路径、无文件时单独执行命令、文件命令并行与分别取消、持续发现 / 断线重连、模式互斥、注册推送、完成后实际获取 P2P 块及主动下线、空文件、EOF 原因、上传和路径校验。
- `node --test test/webui/session_test.cjs`：明确过期后刷新重试、网络结果不确定时不重复执行、共享令牌刷新、SSE 使用新会话重连。
- 合并回归：首选源不可用时从第二候选源下载、机房局部性与中心播种、注册连接上的协调指令、上传降并发及到期恢复、嵌入式库真实下载与文件名清洗。
- `go vet ./...`、JavaScript 语法检查；Linux amd64 / Windows amd64 编译。
- 本机独立进程通过 WebUI 分发文件夹到发送端指定的绝对目录，比对内容并检查空目录；使用默认随机端口单独执行命令、分发文件、保留做种以及验证后启动的接收端自动加入。
- 本机实测 mDNS 重新搜索及多发送端提示；自动发现仍依赖网络组播条件，可手动连接。
- Windows / Linux 完成构建验证，未在两种系统上进行真实文件系统及跨机器运行测试。
- 未在实体多机局域网进行带宽、磁盘或大规模压力测试，未宣称吞吐提升倍数。
- 文件夹为逐文件提交；中途失败时已提交的文件保留，整份文件夹没有事务回滚。重新探测并允许覆盖后可重试。
- 无持久断点续传、任务历史持久化或 TLS。浏览器文件夹选择 API 不包含空目录；需要保留空目录时应使用本机目录浏览。目录打包和缓存需要额外临时空间。
