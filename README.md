# GoSilver Core

局域网内的文件、文件夹同传分发工具。默认启动内嵌 WebUI，无需 Node.js、前端构建服务或外部静态资源。

## 启动

需要 Go 1.25 或更新版本：

```sh
go run ./cmd
# 或编译后运行
go build -o gosilver ./cmd
./gosilver
```

默认使用随机空闲端口，自动打开 WebUI，并在终端打印实际地址。每个实例只选择一种角色：**分发**或**接收**。停止当前服务后才能切换模式；接收端的“结束任务并下线”会关闭发现循环、连接和做种服务。

```sh
# 直接进入分发模式，自动准备文件或文件夹
go run ./cmd -mode=sender -file=/path/to/folder

# 直接进入接收模式，通过 mDNS 发现发送端并连接
go run ./cmd -mode=receiver

# 明确指定地址时，启动后直接连接此地址（填写发送端界面显示的实际端口）
go run ./cmd -mode=receiver -senderAddr=192.168.1.10:59746

# 同一台机器可以直接启动多个实例，默认端口均自动分配
go run ./cmd -mode=receiver
```

## 分发流程

1. 选择本机文件或目录，或使用浏览器上传文件 / 文件夹，然后准备发送服务。
2. 在其他机器进入接收模式，默认**自动持续轮询 mDNS**。发送端上线后自动连接，断线后自动重新发现并重连；未发现时等待约 2 秒后继续，不需要反复点击。地址始终可编辑，可手动直连；“重新发现并等待任务”会立即重新开启发现。多个在线发送端时保留当前连接或等待手动指定。
3. 发送端勾选接收机器，统一指定目标目录和是否覆盖。
4. 点击“预探测所选机器”，检查路径、文件冲突、写权限和磁盘空间。失败机器显示原因并排除。
5. 点击“开始分发”。接收端启动时再次检查，只有通过检查的机器参与。文件夹保留顶层目录、子目录、空目录和空文件。
6. 查看各机器的进度、平均速度和错误。接收完成后状态变为“接收完成 · 做种中”，保留接收视图并继续提供分块；点击“结束任务并下线”后才是“任务结束”。

也可以点击接收机器区域的“无条件分发”：无需勾选，当前及后续上线设备都会自动预探测并加入**同一次任务**，目标不可用的机器仍会警告并排除。“停止接纳新设备”只关闭后续加入，已有机器继续接收和做种。

接收端没有保存根目录配置。**保存位置完全由发送端指定**，绝对路径按接收端操作系统解释；相对路径以接收端程序的工作目录为基准。发送端的“选择位置”浏览所选第一台机器的实际文件系统；对其他机器使用该位置时会分别预探测。

每次分发后需要重新预探测，避免重复分发时沿用旧的文件检查结果。若源文件在准备后被修改，服务会返回具体原因，需要停止并重新准备。

## 命令执行

接收端**默认允许**发送端执行命令，控制密钥可选。进入分发模式后发送服务立即可用，在“命令执行”中勾选机器即可运行，**无需准备文件**。命令与文件各自显示状态、输出和取消入口，可以同时运行，执行命令不打断做种。

- macOS / Linux 使用 `/bin/sh -c`，Windows 使用 `cmd.exe /C`。
- 工作目录由发送端指定，默认 `.`。
- 默认超时 60 秒，最长 300 秒；输出上限 256 KiB。
- 取消任务时会终止进程及其子进程。
- 如需关闭命令执行，接收端启动参数使用 `-allowCommands=false`。

设置可选密钥时，接收端和发送端填写相同值。也可通过环境变量设置，避免出现在命令行中：

```sh
GOSILVER_TOKEN='your-shared-key' go run ./cmd -mode=receiver
```

TCP 控制与文件数据用于可信局域网，当前未提供 TLS 加密。WebUI 只绑定本机回环地址，并检查会话令牌、来源和 Host。

## 参数

| 参数 | 默认值 | 用途 |
|---|---|---|
| `-mode` | 空 | `sender` / `receiver`，为空时展示模式选择 |
| `-file` | 空 | 分发文件或文件夹 |
| `-senderAddr` | 空 | 接收端启动时先直连此地址，随后持续发现；为空时自动发现 |
| `-listen` | `:0` | 分发端 TCP 监听地址，默认随机空闲端口 |
| `-webAddr` | `127.0.0.1:0` | 本机 WebUI 地址，默认随机空闲端口 |
| `-noBrowser` | `false` | 不自动打开浏览器 |
| `-token` | `GOSILVER_TOKEN` | 可选控制密钥 |
| `-allowCommands` | `true` | 接收端命令执行开关 |

WebUI、分发端和接收端 P2P 端口均默认自动分配；mDNS 发布实际分配的发送端端口。需要固定端口时仍可显式指定参数。mDNS 发布失败不会阻止发送服务启动，可以通过界面显示的地址手动连接。

## 实现

- GSP TCP 协议：1 字节类型 + 4 字节长度 + payload。
- 每块 **4 MiB**；CRC32 校验后直接写入临时文件，完成并同步落盘后重命名。
- 下载采用 5 个工作协程、每块最多 3 次尝试；调度按机房局部性、速度及租约负载返回最多 3 个候选源，逐个故障转移并由源机器兜底。
- 协调器的补种请求进入同一组有界下载协程，避免重复写块；慢源降并发指令到期自动恢复。
- 每地址最多 10 个借出或空闲连接；支持拨号超时、取消和连接池关闭，淘汰空闲一分钟的连接，每次响应刷新截止时间。
- 上传并发为 8；内存缓冲区延迟分配，最多缓存 16 个，不因缓冲池耗尽阻塞。
- 文件夹采用不压缩的 tar 流式打包，避免额外压缩 CPU 开销；接收时校验清单，拒绝越界路径、归档链接和特殊文件。
- WebUI 操作异步返回，SSE 每 400ms 检查状态，仅在变化时推送，按钮即时反馈并防止重复提交。
- 页面会话过期时自动恢复令牌并重连状态推送，保留表单；仅重试明确因会话过期而被拒绝的请求，避免网络中断后重复发起任务。

浏览器上传上限 64 GiB，一次文件夹最多 10,000 个条目。文件夹发送需要额外的本地打包空间；接收时需要同时容纳归档和展开内容。直接选择本机文件不受浏览器上传上限限制。

## 验证

```sh
go test ./...
go test -race ./...
go vet ./...
node --test test/webui/session_test.cjs
go test ./pkg/mempool -run '^$' -bench . -benchmem
```

测试不依赖外部 `test.apk`、固定端口或手工启动的服务。覆盖多机分发、后续设备自动加入、失败机器排除、目录还原、P2P 继续做种与下线、独立命令与文件并行、EOF 原因、取消、路径验证、上传、单模式互斥、持续发现和会话恢复。Node.js 仅用于会话脚本测试，运行程序无需 Node.js。

审计结论与验证边界见 [docs/AUDIT.md](docs/AUDIT.md)。
